# GT63 Brand Documentation

Version: 1.0

Status: CANONICAL

Approved: Founder

Lock: GT63 BRAND LAYER v1.0 LOCKED

## Purpose

This folder contains the permanent Brand Layer of GT63. These documents are internal source-of-truth materials for future AI systems, developers, designers and product contributors.

They are not marketing pages. They are not user documentation. They define how GT63 should feel, speak and present travel decisions.

These documents are Version 1.0 of the GT63 Brand Layer. They are expected to evolve over time through v1.1, v2.0 and future versions. Future versions should extend the philosophy without rewriting its foundation.

The Brand Layer must outlive the software. Avoid tying these documents to current tools, frameworks, rendering methods, engines or implementation details.

## Documents

### GT63_EXPERIENCE_BIBLE_EN.md

The canonical experience philosophy.

Use this first when making any design, copy, experience, page, interface or presentation decision.

### GT63_EXPERIENCE_BIBLE_BG.md

The Bulgarian internal manifesto.

Use this when working in Bulgarian or when aligning the emotional language of the product with the founder's product intent.

### GT63_DESIGN_RULES.md

The strict design rulebook.

Use this before changing layouts, typography, photography, page rhythm, landing pages or any client-facing visual surface.

### GT63_WORDS.md

The official vocabulary and writing guide.

Use this before writing client-facing copy, interface labels, presentation text, CTA language, marketing language or AI-generated prose for GT63.

## Priority

If the documents appear to overlap, use this priority:

1. `GT63_EXPERIENCE_BIBLE_EN.md`
2. `GT63_DESIGN_RULES.md`
3. `GT63_WORDS.md`
4. `GT63_EXPERIENCE_BIBLE_BG.md`
5. This `README.md`

If brand documentation conflicts with locked product rules, stop and report the conflict. Do not silently redesign a working system to satisfy visual preference.

## Required AI Instruction

Before generating any client-facing presentation, page, interface, experience, visual design or marketing content for GT63, always read:

1. `GT63_EXPERIENCE_BIBLE_EN.md`
2. `GT63_DESIGN_RULES.md`
3. `GT63_WORDS.md`

Every execution must comply with these documents.

## How AI Should Use These Documents

AI systems must treat these files as durable project memory.

Before creating or changing GT63 presentation work, the AI should:

1. Read the canonical experience bible.
2. Read the design rules.
3. Read the vocabulary.
4. Check whether the requested output supports the GT63 North Star.
5. Report any conflict before execution.

## What These Documents Do Not Do

They do not replace operating rules that protect truth, safety, pricing, selection, approved data or product integrity.

They guide the brand and experience layer.

## Maintenance

These documents should change rarely.

Update them only when GT63's long-term brand principles evolve. Do not edit them for short-term campaign copy, temporary UI needs or one-off design preferences.
